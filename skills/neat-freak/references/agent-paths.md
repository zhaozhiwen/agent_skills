# Claude / Codex paths, loading, and size quick reference

Platform mechanisms change. Probe the current environment and this machine's rules first; when writes or size limits are involved, prefer checking the current official docs or the local tool output, and do not treat this table as permanently true.

## General principles

- Distinguish three kinds of files: human-maintained rules, agent auto memory, and machine-generated history/indexes. They cannot share one set of write rules.
- `MEMORY.md` is just a file name; it does not mean the same thing across platforms. Size thresholds must be tied to a platform and a file type.
- The canonical rule file may be CLAUDE.md, AGENTS.md, an override, an import, or a symlink; go by what the current workspace declares and the actual load chain.
- Finding several platform directories does not mean every platform is in use. Audit only the platform currently running and the install surfaces the user explicitly includes.

## Claude Code

| Purpose | Common path / rule |
|---|---|
| User instructions | `~/.claude/CLAUDE.md` |
| Project instructions | `./CLAUDE.md`, `./.claude/CLAUDE.md`, `CLAUDE.local.md` |
| Path rules | `.claude/rules/**/*.md` |
| Auto memory | `~/.claude/projects/<project>/memory/` |
| Auto memory index | `MEMORY.md` in the directory above |
| Skills | `~/.claude/skills/<name>/SKILL.md` or the project's `.claude/skills/` |

Current official position:

- CLAUDE.md is loaded in full, but the recommended target is under about 200 lines; the longer it is, the more attention it consumes and the lower the compliance. This is a quality budget, not a hard truncation line.
- Claude auto memory `MEMORY.md` loads only the first 200 lines or 25KB (whichever comes first) at session start; topic files are read on demand. This hard limit belongs only to Claude auto memory and does not apply to Codex generated memory.
- Claude natively reads CLAUDE.md. Projects that already have AGENTS.md can single-source via an import or a symlink; the direction is decided by the project's rules — do not flip it on your own.

## OpenAI Codex

| Purpose | Common path / rule |
|---|---|
| Codex home | `$CODEX_HOME`, default `~/.codex` |
| Global instructions | `$CODEX_HOME/AGENTS.override.md`; if absent, `AGENTS.md` |
| Project instructions | From the project root down to the current directory, look for `AGENTS.override.md`, `AGENTS.md`, and the configured fallbacks at each level |
| User skills | `~/.agents/skills/<name>/SKILL.md` (older Codex versions used `$CODEX_HOME/skills/`) |
| Repo skills | `.agents/skills/<name>/` in the current directory and each parent up to the repo root |
| Admin skills | `/etc/codex/skills/<name>/` |

Current official position: the merged project instruction chain is capped at 32KiB by default, controlled by `project_doc_max_bytes`; instructions closer to the current directory load later. Check overrides and fallbacks — do not only look for the root AGENTS.md.

Some Codex environments also provide `~/.codex/memories/`, rollout summaries, or Chronicle-derived indexes. These files may be generated by the host pipeline:

- First read the memory instructions given by the current environment; without explicit authorization, treat them as read-only.
- Do not directly edit generated `MEMORY.md`, `memory_summary.md`, `raw_memories.md`, or rollout summaries.
- When the user explicitly asks to update memory and the environment allows it, use only the correction input that this Codex environment specifies, or control generation and use through the official `/memories`, settings, and `memories.*` config, then wait for the host's consolidation; do not set your own file-size targets, compaction candidates, or project-level generated-memory gates.

When you find files such as `TEAM_GUIDE.md` or `.agents.md`, treat them as instruction files only if they appear in Codex's fallback config.

## Other Agent Skills platforms (Qoder, Kimi Code, iFlow, CodeBuddy, Cursor, Gemini CLI, etc.)

Agent Skills is an open standard (opened by Anthropic in 2025-12), and about 40 products are compatible with this skill's distribution format. Platforms other than Claude Code and Codex do not get individual quick-reference tables; use the generic probing method:

1. **Rule files**: in the project root and parent directories, look for `AGENTS.md` (the de facto cross-platform standard), `CLAUDE.md`, and platform-specific forms (such as `.cursor/rules/`, `.cursorrules`, project instructions in platform settings). Which one is actually loaded is decided by the current platform's docs and diagnostic entry points — do not guess.
2. **Three-way classification**: put every knowledge file you find into one of three categories — human-maintained rules, agent auto memory, machine-generated history/indexes. When the category is unclear, treat it as machine-generated (the most conservative choice).
3. **Memory boundary**: if no official control surface can be found for an unknown platform's memory mechanism, default to read-only; do not apply any other platform's size thresholds or write rules to it.
4. **Fallback usage**: when the host does not support Agent Skills, this skill still works — hand the full SKILL.md to the agent as a rule file or as conversation instructions, and follow up with the references content as needed; the execution boundaries stay the same.

## Coexistence check

1. List the platform directories that actually exist and the skills' realpaths.
2. Check whether same-name skills are symlinked to the same canonical copy, installed as copies, or overridden by a higher-priority version.
3. Edit only the authoritative canonical copy; copy-based installs need an explicit sync mechanism — do not assume they update automatically.
4. Symlinks may be unavailable on Windows or in restricted environments; a project may use imports or generated mirrors instead, as long as the workspace rules are explicit and there is a consistency gate.
5. Verify loading, not just file existence: use the instruction/skill list, `/memory`, status, or an equivalent diagnostic entry point the platform provides.
